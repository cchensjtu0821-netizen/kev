## 模式

16 种标准模式：雨景、剪影、全景、夜景、舞台、原生、球类、设施、车流、月亮、动物、博物馆、小烟花、大烟花、仙女棒、文档。

- 原生单独出现 3,188 次；另有原生与大烟花、小烟花、仙女棒分别共现 1 次。用户将这 3 条视为噪声，业务规则是选原生时不能再选其他模式。生成训练标签前须核对并修正这 3 条，而不是只在推理时掩盖。
- 已观察到的可叠加组合及次数：夜景+大烟花 393、夜景+小烟花 269、仙女棒+夜景 184、夜景+月亮 94、夜景+车流 82、全景+夜景 64、夜景+舞台 50、夜景+雨景 49、全景+剪影 47；也有全景+夜景+车流等三标签组合。
- 动物、博物馆、文档在用户报告的 GT 中从不与其他模式共现。

## 训练数据构造待验证方案

先以 16 道模式 `noul` 加 8 道色卡组内 `choice` 作为基线。天气组只有一个标签，加“无”后等价于 `noul`；色调组的 `choice` 不加“无”，其余组均加“无”。模式允许叠加，不能合并成一道单选 `choice`。`choice` 组内互斥由概率归一化保证，跨组输出仍可共存；原生与其他模式的互斥需要标签清理和预测后规则。此编码约 24 道题，而非每张图 39 道 `noul`。

保留 39 道 `noul` 作为对照实验，按原图或场景切分训练、验证和测试，比较图片级标签集合准确率、各标签召回率及各组概率校准。不要把同一图的 39 道题当作 39 张独立图；稀有标签如混合色调只有 4 个正例。训练前确认每个 `false` 都表示已检查并确定缺失，而非未标注。

用户提供的汇总标签与示例 JSON 相互矛盾：汇总为原生、室内、冷调；JSON 为剪影、室外、暖调，另有暖色系天空、夕阳、其他建筑。这些数据若指同一图片，必须先确认哪套是 GT。

Kev 的图像路径见 `docs/vision-training.md`。普通文本训练入口不读取 `image`；图像训练入口逐图读取图片，并对该图所有题目的交叉熵取平均。当前图像模型每题运行一个独立的语言模型分支，所以题目数也影响训练成本。发布的文本 checkpoint 没有图像输入能力，图像路径仍属实验性，以上编码优劣需要同一图像验证集的实测结果确认。

转换现有 39 道 `noul` 的 JSONL：

```bash
python scripts/convert_vision_labels.py /data/train.jsonl /data/train-24.jsonl
```

输出文件须与输入文件在同一目录，确保相对 `image` 路径仍有效。脚本保留 `id`、`image`、`state` 等顶层字段，严格检查 39 道题、组内冲突和色调必选；天气仍为 `noul`，其余 7 组为 `choice`。如果原生与其他模式共现，默认停止并指出行号；人工核查后可选择 `--native-conflict drop-native` 或 `drop-others`。脚本接受 `seka_餐饮美食` 作为 `seka_美食` 的别名，但如果已有的 `seka_美食:false` 是错误 GT，仅靠这份 JSONL 无法推断真实值，须先从原始标注修正。
